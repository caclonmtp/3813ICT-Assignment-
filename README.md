# Mean Chat – Repository Documentation

## Overview
A simple chat application split into a Node/Express API server and an Angular client. Data persists to a JSON file for ease of development. Authentication is header-based via an Angular HTTP interceptor that sends `x-user-id` after login.

- Server base URL: `http://localhost:3000/api`
- Client dev server: Angular (default `http://localhost:4200` when using `ng serve`)

Key entry points:
- server/server.js:1
- client/chat/src/app/app.module.ts:1

## Repository Organization & Git Usage
- Root layout:
  - `server/`: Express API, modular routes, in-repo JSON “DB”.
  - `client/`: Angular application (`chat` workspace).
- Suggested Git workflow:
  - Branching: `main` for stable; feature branches `feature/server-*`, `feature/client-*` for scoped changes.
  - Update cadence: small, frequent commits per feature with focused scopes (routes, components, services) and clear messages.
  - PRs: open from feature branches into `main`; review by comparing server and client changes that pair together (e.g., adding a route and the consuming service method).

## Data Structures

### Server-Side Schema
Stored in `server/data/bd.json` and managed via utilities in server/lib/db.js:1.

- User
  - `id: string`
  - `username: string`
  - `email: string`
  - `password: string` (not returned by APIs)
  - `roles: string[]` (e.g., `user`, `group-admin`, `super-admin`)
  - `groups: string[]` (optional; not relied on by server logic)
- Group
  - `id: string`
  - `name: string`
  - `createdBy: string` (user id)
  - `admins: string[]` (user ids)
  - `members: string[]` (user ids)
  - `createdAt: number` (epoch ms)
- Channel
  - `id: string`
  - `groupId: string`
  - `name: string`
  - `createdBy: string`
  - `createdAt: number` (epoch ms)
  - `bannedUserIds?: string[]`
- Message
  - `id: string`
  - `groupId: string`
  - `channelId: string`
  - `userId: string`
  - `username: string`
  - `content: string`
  - `timestamp: number` (epoch ms)

IDs are generated by `genId()` in server/lib/db.js:1.

## API Reference
Base: `http://localhost:3000/api` (JSON responses)

### Auth
- POST `/auth/login`
  - Body: `{ username, password }`
  - 200: `{ success: true, user }` (no password)
  - 401: `{ success: false, message }`
- POST `/auth/register`
  - Body: `{ username, email, password }`
  - 200: `{ success: true, user }`
  - 400/409 on validation

### Users (requires `x-user-id`)
- GET `/users` → `User[]` (no password)
- GET `/users/:id` → `User` (no password)
- PUT `/users/:id`
  - Permitted: self or super-admin
  - Body: any of `{ username, email, roles }` (roles only by super)
  - 200: updated `User` (no password)
- PATCH `/users/:id/roles` (super only)
  - Body: `{ roles: string[] }`
  - 200: updated `User` (no password)
- POST `/users/:id/promote` (super only)
  - Promotes to `group-admin` if not already
  - 200: updated `User` (no password)
- DELETE `/users/:id` (super only)
  - Removes user and cleans groups/admins; reassigns `createdBy` if needed
  - 200: `{ success: true }`

### Groups (requires `x-user-id`)
- GET `/groups`
  - Super: all groups; others: only groups where user is member/admin
  - 200: `Group[]`
- GET `/groups/user/:userId`
  - Super: all groups; others: groups for given user
  - 200: `Group[]`
- POST `/groups`
  - Roles: `group-admin` or `super-admin`
  - Body: `{ name }`
  - 200: `{ success: true, group }`
- DELETE `/groups/:groupId`
  - Only group owner (`createdBy`) or super-admin
  - Cascades: deletes channels and messages in group
  - 200: `{ success: true }`
- POST `/groups/:groupId/members`
  - Admins or super only
  - Body: `{ userId }`
  - 200: updated `Group`
- DELETE `/groups/:groupId/members/:userId`
  - Admins or super only
  - 200: updated `Group`
- POST `/groups/:groupId/channels/:channelId/ban`
  - Admins or super only
  - Body: `{ userId }`
  - 200: `{ success: true, channel }`

### Channels (requires `x-user-id`)
- GET `/channels/group/:groupId` → `Channel[]`
- POST `/channels`
  - Admins of group or super only
  - Body: `{ name, groupId }`
  - 200: created `Channel`
- DELETE `/channels/:channelId`
  - Admins of channel’s group or super only
  - Cascades: removes messages in channel
  - 200: `{ success: true }`

### Messages (requires `x-user-id`)
- GET `/messages?groupId&channelId`
  - Returns last 50 sorted ascending
  - 200: `{ success: true, messages: Message[] }`
- POST `/messages`
  - Body: `{ groupId, channelId, content }`
  - Validates channel and bans; sets `userId`, `username`, `timestamp`
  - 200: `{ success: true, message }`

## Client–Server Interaction Details

### Authentication & Identity
- Login/Register handled by `AuthService` (client/chat/src/app/services/auth.service.ts:1) against `/auth/*` endpoints.
- On successful login, the user object is stored in `localStorage` under `currentUser`.
- An HTTP interceptor (client/chat/src/app/interceptors/auth.interceptor.ts:1) reads `currentUser` and injects `x-user-id` for all requests that require authentication.
- Route guarding and role checks handled by `AuthGuard` (client/chat/src/app/guards/auth.guard.ts:1) using `route.data.roles`.

### Dashboard
- Loads groups for the current user via `GET /groups` and, per group, loads channels via `GET /channels/group/:groupId` (client/chat/src/app/components/dashboard/dashboard.component.ts:1).
- UI updates: component state arrays (`groups`, `channels[groupId]`) are replaced; Angular template iterates and renders accordingly.

### Admin & Group Admin
- Create group → POST `/groups` with `{ name }`; server sets `createdBy`, adds creator to `admins` and `members`.
- Create channel → POST `/channels` with `{ name, groupId }`.
- Add/remove group member → POST/DELETE `/groups/:groupId/members`.
- Delete channel/group → DELETE respective routes; UI refreshes by reloading group details or list.
- Ban user from channel → POST `/groups/:groupId/channels/:channelId/ban`.
- Components: client/chat/src/app/components/admin/admin.component.ts:1 and client/chat/src/app/components/group-admin/group-admin.component.ts:1

### Chat
- Loads group/channel info from `/groups` and `/channels/group/:groupId` to display names.
- Messages: currently stored in `localStorage` per channel in ChatComponent (client/chat/src/app/components/chat/chat.component.ts:1). The server provides `/messages` endpoints for persistence and multi-user sync; migrating ChatComponent to use them would switch to real-time-ish behavior by polling or websockets (future enhancement).
- UI updates: pushing to `messages` array triggers re-render; scroll-to-bottom done via DOM query.

### Error/Confirm UX
- `NotifyService` exposes a `BehaviorSubject` of toasts consumed by `ToastsComponent` to show transient alerts.
- `ConfirmService` shows a modal via `ConfirmComponent` and returns a Promise that resolves on user action.

## Setup & Run

### Server
- Requirements: Node 18+
- Install: `cd server && npm install`
- Run: `npm start`
- API runs at `http://localhost:3000/api`
- Data file auto-created at `server/data/bd.json` with a default super user if missing (server/lib/db.js:1).
  - Default super credentials: `username: super`, `password: 123`

### Client
- Requirements: Node 18+, Angular CLI (optional for global `ng`)
- Install: `cd client && npm install`
- Run: `npm start` (Angular dev server, typically `http://localhost:4200`)
- Ensure server is running at `http://localhost:3000` for API calls.

## Notes & Future Improvements
- Chat persistence: Switch ChatComponent to use `/api/messages` instead of `localStorage` for real multi-user chat. Add periodic polling or WebSocket for live updates.
- Authorization: Consider JWT or session auth instead of `x-user-id` header in production. Add password hashing.
- Validation: Harden server-side validation for payloads and roles.
- Pagination: Add pagination for groups/channels/messages where needed.
